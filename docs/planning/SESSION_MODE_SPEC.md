## 1. 功能概述

### 1.1 定位

| 頁面 | 使用者 | 情境 | 功能 |
|------|--------|------|------|
| `workout_execution_page` | 學員 | 自主訓練 | 記錄重量/次數 |
| `session_mode_page` ⭐ | 教練 | 帶學員上課 | 記錄 + 筆記 + 問卷 + 統計 |

### 1.2 進入點

教練可從以下位置進入 Session Mode：

1. **教練行事曆** → 點擊預約課程 → 「開始上課」
2. **學員詳情頁** → 今日/下堂課程卡片 → 「開始上課」
3. **首頁「下堂課」卡片** → 「開始上課」

### 1.3 設計原則

- **混合式介面**：結構化數據 + 自由筆記並存
- **最少切換**：訓練、筆記、統計在同一頁面
- **快速輸入**：PREV 預填、一鍵複製、動作歷史

## 3.7 課前問卷系統 (Pre-Session Readiness)

### 3.6.1 五個核心指標（基於 Hooper Index）

| # | 維度 | 問題 | 評分 | 權重 | 表情變化 |
|---|------|------|------|------|----------|
| 1 | 睡眠品質 | 昨晚睡得香嗎？ | 1-5 | 30% | 😴→🥱→😐→🙂→😃 |
| 2 | 睡眠時長 | 昨晚睡了幾小時？ | 3-12hr | 10% | 數字滑桿 |
| 3 | 肌肉狀態 | 身體感覺痠痛嗎？ | 1-5 | 25% | 🤕→😣→😐→💪→⚡ |
| 4 | 心理壓力 | 最近壓力大嗎？ | 1-5 | 20% | 🤯→😓→😐→😌→🧘 |
| 5 | 能量水平 | 今天有想練的感覺嗎？ | 1-5 | 15% | 😴→😑→😐→😊→🔥 |

### 3.6.2 紅綠燈計算規則（簡單閾值）

```
總分計算：
各指標分數（1-5）× 權重 × 20 = 換算成 0-100

範例：
睡眠品質 4 × 0.30 × 20 = 24
睡眠時長 7hr → 換算 4 分 × 0.10 × 20 = 8
肌肉狀態 4 × 0.25 × 20 = 20
心理壓力 4 × 0.20 × 20 = 16
能量水平 4 × 0.15 × 20 = 12
總分 = 80 → 🟢 綠燈

狀態判定：
🟢 綠色：總分 ≥ 70
🟡 黃色：50 ≤ 總分 < 70
🔴 紅色：總分 < 50 或 任意單項 = 1
```

### 3.6.5 資料庫設計

**新增表 `daily_readiness`**：

```sql
CREATE TABLE public.daily_readiness (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  
  -- 關聯
  user_id UUID REFERENCES public.users(id) NOT NULL,
  appointment_id UUID REFERENCES public.appointments(id),
  session_note_id UUID REFERENCES public.session_notes(id),
  
  -- 日期（一日一筆）
  log_date DATE NOT NULL DEFAULT CURRENT_DATE,
  
  -- 量化指標
  readiness_score INTEGER CHECK (readiness_score BETWEEN 0 AND 100),
  traffic_light TEXT CHECK (traffic_light IN ('RED', 'AMBER', 'GREEN')),
  
  -- 詳細數據（JSONB）
  metrics JSONB NOT NULL,
  -- 結構：{
  --   "sleep_quality": 4,      // 1-5
  --   "sleep_hours": 7,        // 3-12
  --   "soreness": 3,           // 1-5
  --   "stress": 4,             // 1-5
  --   "energy": 4,             // 1-5
  --   "notes": "昨天有慢跑"     // 選填
  -- }
  
  -- 時間戳
  created_at TIMESTAMPTZ DEFAULT now(),
  
  -- 一日一筆約束
  UNIQUE(user_id, log_date)
);

-- RLS 政策
ALTER TABLE public.daily_readiness ENABLE ROW LEVEL SECURITY;

-- 學員可以管理自己的
CREATE POLICY "Users can manage own readiness"
  ON public.daily_readiness FOR ALL
  USING (auth.uid() = user_id);

-- 教練可以查看自己學員的
CREATE POLICY "Coaches can view students readiness"
  ON public.daily_readiness FOR SELECT
  USING (
    EXISTS (
      SELECT 1 FROM coaching_relationships
      WHERE coach_id = auth.uid() 
        AND client_id = daily_readiness.user_id
        AND status = 'active'
    )
  );

-- 索引
CREATE INDEX idx_readiness_user_date ON daily_readiness(user_id, log_date DESC);
CREATE INDEX idx_readiness_appointment ON daily_readiness(appointment_id);
```

## 4. 資料流程

### 4.0 預約確認時自動創建資料

當預約狀態變為 `confirmed` 時，系統自動創建相關資料：

```
appointments.status = 'confirmed'
     │
     ▼
觸發 Database Function 或 Edge Function
     │
     ├── 創建 session_notes（空的）
     │   └── appointment_id = 本次預約
     │
     └── 創建 daily_readiness（未填寫）
         ├── appointment_id = 本次預約
         ├── log_date = 預約日期
         └── metrics = NULL（表示未填寫）

不預先創建：
├── workout_plans（教練在 Session Mode 中決定是否建立）
└── 統計數據（上課前再即時查詢）
```

**學員視角**：
- 預約確認後，學員在訓練行事曆上可以看到這堂課
- 課前收到提醒 → 填寫問卷
- 教練建立訓練計畫後，學員可以查看（只能看不能改）

**教練視角**：
- 預約確認後，可以進入課程頁面建立訓練計畫
- 上課當天進入 Session Mode

### 4.1 進入頁面時載入

```
1. 載入 appointment 資訊（時間、學員）
2. 載入 workout_plan（可能已有教練預先安排的內容）
3. 載入 session_note（已存在，可能有內容）
4. 載入 daily_readiness（檢查學員是否已填問卷）
5. 載入 exercise_history（各動作的上次訓練數據）
6. 即時查詢 recent_statistics（近 7 天統計）
```

### 4.3 查詢動作歷史

```sql
-- 查詢某學員某動作的最近 5 次訓練
SELECT 
  wp.scheduled_date,
  wp.id as workout_plan_id,
  exercise->'sets' as sets
FROM workout_plans wp,
     jsonb_array_elements(wp.exercises) as exercise
WHERE wp.user_id = '學員ID'
  AND exercise->>'exercise_id' = '動作ID'
  AND wp.completed = true
ORDER BY wp.scheduled_date DESC
LIMIT 5;

-- 查詢 PR
SELECT max_weight, max_reps, achieved_date
FROM personal_records
WHERE user_id = '學員ID'
  AND exercise_id = '動作ID';
```

## 7. 特殊規則

### 7.1 Session Mode 下教練可以打勾

**現有規則**（v2.9.1）：
- 教練不能對學員的訓練 set 打勾（任何時間）
- 這是為了防止教練誤操作學員的個人紀錄

**Session Mode 例外**：
- 在 Session Mode 頁面中，教練可以對 set 打勾
- 因為這是「教練帶學員上課」的情境，教練需要記錄

**判斷條件**：
```dart
bool canCoachMarkSet = isSessionMode && isWithinTimeWindow;

// isSessionMode：當前在 Session Mode 頁面
// isWithinTimeWindow：課程開始後 4 小時內

// 範例：課程 19:00 開始
// - 教練可打勾時間：19:00 ~ 23:00
// - 19:00 之前：不能打勾（課程尚未開始）
// - 23:00 之後：不能打勾（超過 4 小時）
```

### 7.2 教練編輯權限時間表

| 時段 | 編輯動作/組數 | 打勾 |
|------|--------------|------|
| 課前（開始前） | ✅ 可以 | ❌ 不可以 |
| 課中（開始後 4 小時內） | ✅ 可以 | ✅ 可以 |
| 課後（超過 4 小時） | ❌ 不可以 | ❌ 不可以 |

### 7.3 Session Mode 下學員權限

當 `workout_plan` 屬於 Session Mode（有 `appointment_id`）：

| 操作 | 學員權限 |
|------|----------|
| 查看訓練計畫 | ✅ 可以 |
| 修改訓練計畫 | ❌ 不可以 |
| 對 set 打勾 | ❌ 不可以 |
| 新增/刪除動作 | ❌ 不可以 |
| 填寫課前問卷 | ✅ 可以 |
| 課後查看訓練紀錄 | ✅ 可以 |

**教練完全控制 Session Mode 的訓練內容**。

### 7.2 教練可手動建立 Session

**正常流程**：
- 學員預約 → 教練確認 → 自動創建資料

**例外流程**（臨時預約）：
- 學員臨時跟教練約（未透過 App）
- 教練可以「手動建立 Session」

**教練手動建立 Session**：
```
教練端：
┌─────────────────────────────────────────────────────────────┐
│ + 建立臨時課程                                               │
├─────────────────────────────────────────────────────────────┤
│ 學員：[Amy ▼]                                                │
│ 日期：[2026-01-10]                                           │
│ 時間：[19:00 - 20:00]                                        │
│                                                              │
│                    [建立並開始上課]                           │
└─────────────────────────────────────────────────────────────┘
```

**系統行為**：
1. 創建 `appointments`（狀態直接為 `confirmed`）
2. 自動創建 `session_notes`、`daily_readiness`、`workout_plans`
3. 直接進入 Session Mode

### 7.4 預約時間限制

- **學員**：只能預約未來的時段
- **教練**：可以建立「當下」的臨時課程（手動建立）

### 7.5 預約取消後的資料處理

預約取消後，相關資料**保留不刪除**：

```
appointments.status = 'cancelled'
     │
     └── 保留：
         ├── session_notes（保留）
         ├── daily_readiness（保留）
         └── workout_plan（保留）

用途：
- 後台表現統計
- 健身房可檢視教練的教學情況
- 取消率分析
```

### 7.6 課程結束流程

教練按「結束課程」按鈕：

```
┌─────────────────────────────────────────────────────────────┐
│ Session Mode                                        [結束課程]│
│ Amy・1/10 19:00                                              │
└─────────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 確認結束課程？                                               │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│ ⚠️ SOAP 筆記尚未填寫                                         │
│    [主觀] ❌  [客觀] ❌  [評估] ❌  [計畫] ❌                  │
│                                                              │
│ 訓練內容將自動儲存                                           │
│                                                              │
│        [繼續編輯筆記] [稍後填寫] [確認結束]                   │
└─────────────────────────────────────────────────────────────┘
                           │
                           ▼
           appointments.status = 'completed'
                           │
                           ▼
           學員可在行事曆上看到「已完成」標籤
```

**SOAP 提醒機制**：
- 結束時檢查 SOAP 是否已填
- 若未填完，顯示警告但不強制
- 教練可選擇「繼續編輯」、「稍後填寫」或「確認結束」

**時間提醒**：
- 預約結束時間前 5 分鐘提醒教練
- 可以超時繼續上課（開始後 4 小時內都可操作）

### 7.7 資料儲存機制（v3.1 更新）

```
Session Mode 儲存策略（即時保存）：

┌─ 即時上傳 DB ──────────────────────────────────────────────┐
│ - 所有訓練修改（重量、次數、新增/刪除動作/組數）            │
│ - 勾選完成 set（✓）                                        │
│ - SOAP 筆記（Debounced 1 秒自動保存）                      │
│ - 照片上傳                                                 │
│ - 手繪保存                                                 │
└────────────────────────────────────────────────────────────┘

App 進入背景/頁面離開時：
- 自動保存所有未保存資料
```

### 7.8 Realtime 同步機制（v3.1 新增）

教練與學員之間的即時同步：

**訂閱表格**：
- `workout_plans`：訓練動作、組數、打勾狀態、運動時長
- `session_notes`：SOAP 筆記、照片、手繪、快速標籤

**訂閱條件**（避免不必要訂閱）：
```dart
bool shouldSubscribe = isSessionPlan || traineeId != currentUserId;

// isSessionPlan: 有 appointment_id 的訓練計畫
// traineeId != currentUserId: 教練在追蹤學員訓練
```

**智慧判斷**：
| 情境 | Realtime | 說明 |
|------|----------|------|
| 學員執行自己訓練 | ❌ | traineeId == currentUserId |
| 教練 Session Mode | ✅ | isSessionPlan = true |
| 學員 Session Mode | ✅ | isSessionPlan = true |
| 教練遠端追蹤學員 | ✅ | traineeId != currentUserId |

**防抖機制**（避免自己觸發的更新閃爍）：
```dart
// 本地保存後 2 秒內收到的 Realtime 更新忽略
DateTime? _lastLocalSaveTime;
bool _shouldIgnoreRealtimeUpdate() {
  if (_lastLocalSaveTime == null) return false;
  return DateTime.now().difference(_lastLocalSaveTime!) < Duration(seconds: 2);
}
```

**計時器狀態處理**：
- 初次載入 `in_progress` → `paused`（提示繼續訓練）
- Realtime 更新保持 `in_progress`（不中斷教練計時）
