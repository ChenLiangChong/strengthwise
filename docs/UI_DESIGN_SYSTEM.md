# StrengthWise - UI 設計系統

> 設計理念與決策原因

**版本**：1.0  
**最後更新**：2026年1月5日

---

## 1. 設計哲學

### 1.1 核心願景

StrengthWise 的 UI 設計旨在建立一個**專業、高效、無干擾**的健身記錄體驗。

> 優秀的健身 App UI 不僅是讓使用者「看見」數據，更是透過互動設計引導使用者進入「心流（Flow）」狀態，讓記錄訓練成為一種直覺且愉悅的儀式。

### 1.2 設計原則優先順序

1. **功能優先**：記錄效率 > 視覺華麗
2. **清晰層次**：資訊階層明確，一眼找到重點
3. **環境適應**：深淺模式適應不同訓練環境
4. **觸控友善**：考慮訓練時手部顫抖、有汗的情況

## 2. 競品分析與借鏡

### 2.1 現代健身 App 趨勢

| 競品 | 核心特色 | 借鏡之處 |
|------|---------|----------|
| **Hevy** | 社群化佈局、動態卡片 | 每個 Set 的完成都有明確視覺回饋 |
| **Strong** | 極簡高對比深色模式 | 在低光源環境下的高對比度設計 |
| **Fitbod** | 預測性導航 | 自動聚焦未完成的 Set，減少點擊次數 |

### 2.2 StrengthWise 差異化

- **專注記錄**：不做社群功能，專注訓練記錄效率
- **教練整合**：支援教練學員雙向互動
- **數據導向**：等寬字體顯示數據，專業感

## 3. 色彩設計理由

### 3.1 為何選擇 Titanium Blue？

- **專業感**：藍色調傳達可靠、專業的品牌形象
- **中性**：適合男女使用者，不會過於陽剛或柔和
- **對比度**：藍色在深淺模式都能維持良好對比

### 3.2 深淺模式設計考量

**淺色模式**：
- 使用 `#F1F5F9`（冷灰白）而非純白，讓白色卡片能透過邊框凸顯層次
- 適用於日間或明亮健身房，抵抗環境反光

**深色模式**：
- 使用 `#0F172A`（深岩灰）而非純黑，避免 OLED 拖影
- 主色降飽和（`#2563EB` → `#60A5FA`），避免「震動感」
- 適用於夜間或強調專注的訓練環境

### 3.3 語意化色彩

定義顏色的「功能」而非「色相」：
- **Primary**：核心行動（開始訓練、確認）
- **Success**：完成狀態（勾選組數、PR 達成）
- **Error**：刪除、錯誤
- **Warning**：休息時間結束提醒

## 4. 字體設計理由

### 4.1 為何採用雙字體策略？

| 字體類型 | 推薦字體 | 選擇理由 |
|---------|---------|---------|
| **主要字體** | Inter / Manrope | 高 x-height，小字號清晰可辨 |
| **數據字體** | JetBrains Mono | 等寬防止數字跳動，專業儀表板感 |

### 4.2 等寬字體的重要性

計時器使用等寬字體可防止 `09:59` → `10:00` 時的視覺跳動，賦予介面精密儀表板的專業感。

### 4.3 深色模式字重考量

過細字體（Light/Thin）在黑色背景會因**光暈效應（Halation）**而模糊，深色模式最小字重應為 Regular (400)。

## 5. 網格系統理由

### 5.1 為何使用 8 點網格？

- **視覺一致性**：所有元素對齊，專業感
- **開發效率**：減少討論「12 還是 13」的問題
- **Material 3 相容**：與 Flutter 設計系統一致

### 5.2 觸控目標設計

基於**菲茨定律（Fitts's Law）**：
- 觸控目標最小高度：48dp
- 考慮訓練時手部顫抖、有汗的情況
- 全寬度滑動手勢替代小按鈕

---

## 6. 無障礙考量

### 6.1 對比度標準

遵循 WCAG AA 標準：
- 常規文字對比度至少 4.5:1
- 大標題對比度至少 3:1
- 避免使用過淺的灰色

### 6.2 動態字級

支援系統字體縮放，使用 `Flexible` / `Expanded` 確保佈局不崩壞。

### 6.3 觸覺回饋

在關鍵操作點加入 HapticFeedback，讓使用者「感受」到操作。
