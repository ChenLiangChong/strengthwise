# StrengthWise - UI 設計系統

> 設計理念與決策原因

**版本**：2.0  
**最後更新**：2026年1月5日

---

## 1. 設計哲學

### 1.1 核心願景

StrengthWise 的 UI 設計旨在建立一個**專業、高效、無干擾**的健身記錄體驗。

> 優秀的健身 App UI 不僅是讓使用者「看見」數據，更是透過互動設計引導使用者進入「心流（Flow）」狀態，讓記錄訓練成為一種直覺且愉悅的儀式。

### 1.2 設計原則優先順序

1. **功能優先**：記錄效率 > 視覺華麗
2. **清晰層次**：資訊階層明確，一眼找到重點
3. **環境適應**：深淺模式適應不同訓練環境
4. **觸控友善**：考慮訓練時手部顫抖、有汗的情況
5. **設備無關**：同一套設計語言，適配手機、平板、桌面 ⭐ v2.0 新增

## 2. 響應式設計理念 ⭐ v2.0 新增

### 2.1 為何需要企業級響應式架構？

隨著 StrengthWise 轉型為教練-學員雙端平台，使用情境已不再限於手機：

| 角色 | 主要設備 | 使用場景 |
|------|---------|---------|
| **學員** | 手機 | 健身房快速記錄、查看課表 |
| **教練** | 平板/桌面 | 管理多位學員、分析數據、安排課表 |
| **經營者** | 桌面 | 查看報表、管理教練 |

單純的 UI 縮放無法滿足這些差異化需求，必須建立**語義化的響應式架構**。

### 2.2 視窗尺寸等級（7 級精細化斷點）

基於 Material 3 概念，針對 StrengthWise 實際使用情境擴展為 **7 級斷點系統**：

| 等級 | 代碼名稱 | 範圍 | 設計意圖 |
|------|---------|------|---------|
| **Compact-S** | `mobileSmall` | < 360dp | 緊湊單欄：縮小字體間距，防止舊手機溢出 |
| **Compact** | `mobile` | 360-599dp | 單欄佈局：底部導航，全螢幕模態（**基準**） |
| **Compact-L** | `mobileLarge` | 600-719dp | 過渡佈局：可嘗試簡單分欄 |
| **Medium-S** | `tabletSmall` | 720-839dp | 雙欄開始：Navigation Rail |
| **Medium** | `tablet` | 840-1023dp | 雙欄佈局：Master-Detail |
| **Expanded** | `tabletLarge` | 1024-1279dp | 多欄佈局：常駐 Drawer |
| **Large** | `desktop` | ≥ 1280dp | 寬鬆佈局：限制最大寬度，輔助面板 |

**設計理由**：
- 新增 `mobileSmall` 支援舊款手機（如 Realme 7 5G 在特定設定下）
- 細分 Medium 區間以區別 iPad Mini 與大型手機
- Desktop 起始於 1280dp（主流筆電寬度）

### 2.3 導航適配策略

導航是應用程式的骨架，必須隨螢幕尺寸自動切換模式：

| 模式 | 適用斷點 | 設計理由 |
|------|---------|---------|
| **底部導航欄** | `mobileSmall`、`mobile`、`mobileLarge` (< 720dp) | 拇指熱區，單手操作最佳化 |
| **側邊導航軌** | `tabletSmall`、`tablet` (720-1023dp) | 釋放垂直空間，利用較寬邊緣 |
| **常駐側邊欄** | `tabletLarge`、`desktop` (≥ 1024dp) | 顯示完整導航結構，穩定視覺框架 |

**狀態保存原則**：導航模式切換時，必須保留頁面狀態（滾動位置、輸入內容），避免體驗中斷。

### 2.4 內容佈局策略

#### Master-Detail 模式

對於列表-詳情類頁面（學員管理、預約列表）：
- **小螢幕**：堆疊式導航（Push/Pop）
- **大螢幕**：並排顯示，點擊列表更新右側詳情

#### 網格重流

卡片式佈局（動作庫、儀表板）應基於**最大卡片寬度**動態計算欄數，而非固定欄數。這確保卡片在任何螢幕上都維持最佳閱讀尺寸。

#### 最大內容寬度

超寬螢幕（≥1600dp）上，內容區域應限制最大寬度並置中，避免一行文字過長（超過 60-80 字元）影響閱讀。

### 2.5 輸入模式適配

StrengthWise 必須同時服務觸控與滑鼠鍵盤用戶：

| 觸控優先 | 滑鼠鍵盤優先 |
|---------|------------|
| 48dp 觸控目標 | 可精確至 24dp |
| 長按/滑動手勢 | 右鍵選單/快捷鍵 |
| 無懸停狀態 | 懸停預覽互動性 |

**設計理由**：教練在桌面端需要高效的鍵盤操作（如 Ctrl+S 儲存），而學員在手機上需要大按鈕防誤觸。

## 3. 競品分析與借鏡

### 3.1 現代健身 App 趨勢

| 競品 | 核心特色 | 借鏡之處 |
|------|---------|----------|
| **Hevy** | 社群化佈局、動態卡片 | 每個 Set 的完成都有明確視覺回饋 |
| **Strong** | 極簡高對比深色模式 | 在低光源環境下的高對比度設計 |
| **Fitbod** | 預測性導航 | 自動聚焦未完成的 Set，減少點擊次數 |

### 3.2 StrengthWise 差異化

- **專注記錄**：不做社群功能，專注訓練記錄效率
- **教練整合**：支援教練學員雙向互動
- **數據導向**：等寬字體顯示數據，專業感
- **跨設備一致**：手機、平板、桌面統一體驗 ⭐ v2.0 新增

## 4. 色彩設計理由

### 4.1 為何選擇 Titanium Blue？

- **專業感**：藍色調傳達可靠、專業的品牌形象
- **中性**：適合男女使用者，不會過於陽剛或柔和
- **對比度**：藍色在深淺模式都能維持良好對比

### 4.2 深淺模式設計考量

**淺色模式**：
- 使用冷灰白而非純白，讓白色卡片能透過邊框凸顯層次
- 適用於日間或明亮健身房，抵抗環境反光

**深色模式**：
- 使用深岩灰而非純黑，避免 OLED 拖影
- 主色降飽和，避免「震動感」
- 適用於夜間或強調專注的訓練環境

### 4.3 語意化色彩

定義顏色的「功能」而非「色相」：
- **Primary**：核心行動（開始訓練、確認）
- **Success**：完成狀態（勾選組數、PR 達成）
- **Error**：刪除、錯誤
- **Warning**：休息時間結束提醒

## 5. 字體設計理由

### 5.1 為何採用雙字體策略？

| 字體類型 | 選擇理由 |
|---------|---------|
| **主要字體（Inter/Manrope）** | 高 x-height，小字號清晰可辨 |
| **數據字體（JetBrains Mono）** | 等寬防止數字跳動，專業儀表板感 |

### 5.2 等寬字體的重要性

計時器使用等寬字體可防止 `09:59` → `10:00` 時的視覺跳動，賦予介面精密儀表板的專業感。

### 5.3 深色模式字重考量

過細字體（Light/Thin）在黑色背景會因**光暈效應（Halation）**而模糊，深色模式最小字重應為 Regular (400)。

### 5.4 響應式字體縮放 ⭐ v2.0 新增

字體大小應根據螢幕尺寸適度縮放：
- **小螢幕**：略微縮小，確保內容不溢出
- **大螢幕**：適度放大，維持閱讀舒適度
- **縮放限制**：設定最小/最大值，避免極端情況

## 6. 網格系統理由

### 6.1 為何使用 8 點網格？

- **視覺一致性**：所有元素對齊，專業感
- **開發效率**：減少討論「12 還是 13」的問題
- **Material 3 相容**：與 Flutter 設計系統一致

### 6.2 觸控目標設計

基於**菲茨定律（Fitts's Law）**：
- 觸控目標最小高度：48dp
- 考慮訓練時手部顫抖、有汗的情況
- 全寬度滑動手勢替代小按鈕

### 6.3 響應式間距策略 ⭐ v2.0 新增

間距在不同螢幕尺寸下可適度調整，但必須保持 8 點網格對齊：

| 螢幕尺寸 | 間距策略 |
|---------|---------|
| 小型手機 | 使用較小的網格值（8, 12） |
| 標準手機 | 使用標準網格值（16, 24） |
| 平板/桌面 | 可使用較大網格值（24, 32） |

**原則**：縮放後的間距值應對齊到最近的 4dp，維持網格一致性。

## 7. 無障礙考量

### 7.1 對比度標準

遵循 WCAG AA 標準：
- 常規文字對比度至少 4.5:1
- 大標題對比度至少 3:1
- 避免使用過淺的灰色

### 7.2 動態字級

支援系統字體縮放，使用 `Flexible` / `Expanded` 確保佈局不崩壞。

### 7.3 觸覺回饋

在關鍵操作點加入 HapticFeedback，讓使用者「感受」到操作。

### 7.4 鍵盤導航 ⭐ v2.0 新增

桌面端必須支援：
- Tab 鍵焦點遍歷
- 常用快捷鍵（Ctrl+S 儲存等）
- 視覺化的焦點指示器
