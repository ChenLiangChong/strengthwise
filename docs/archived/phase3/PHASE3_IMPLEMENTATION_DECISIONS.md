## 📋 核心決策

### 決策 1: 分階段實作策略

**問題**：完整手繪板功能複雜度高，是否一次完成？

**選項**：
- **選項 A**：分階段實作（Phase 3.0 → 3.1）
- **選項 B**：一次完整實作

**決定**：✅ **選項 A - 分階段實作**

**理由**：
1. **快速交付價值**：照片標註滿足 80% 需求，2-3 天可完成
2. **降低風險**：手繪板技術複雜，需要 1-2 週打磨
3. **用戶反饋**：先驗證教練是否真的需要完整繪圖功能
4. **迭代彈性**：可根據實際使用情況調整 Phase 3.1 範圍

**影響**：
- Phase 3.0 專注於：SOAP 筆記 + 照片上傳 + 簡易標註
- Phase 3.1 延後實作：完整手繪板 + 底圖模板 + 向量編輯

---

### 決策 2: SOAP 格式保留

**問題**：文字備註應該使用 SOAP 格式（4 欄位）還是單一備註欄位？

**選項**：
- **選項 A**：保留 SOAP 格式（Subjective, Objective, Assessment, Plan）
- **選項 B**：簡化為單一備註欄位

**決定**：✅ **選項 A - 保留 SOAP 格式**

**理由**：
1. **專業標準**：SOAP 是醫療與教練領域的標準格式
2. **結構化資料**：支援未來統計分析與搜尋
3. **教練習慣**：專業教練熟悉 SOAP 格式
4. **UI 彈性**：可設計「展開/收合」，不會增加使用複雜度

**實作細節**：
```dart
SoapNoteModel {
  String? subjective;  // 主觀（學員陳述）
  String? objective;   // 客觀（教練觀察）
  String? assessment;  // 評估（專業分析）
  String? plan;        // 計劃（下一步）
}
```

**UI 設計**：
- 預設：顯示合併簡要文字
- 展開：顯示 4 個欄位結構
- 教練可選擇只填部分欄位（非強制）

### 決策 3: 底圖模板提供方式

**問題**：繪圖功能需要的底圖模板由誰提供？

**選項**：
- **選項 A**：開發方提供基礎模板（需繪製）
- **選項 B**：用戶提供或使用免費素材

**決定**：✅ **選項 B - 用戶提供或使用免費素材**

**理由**：
1. **避免延遲**：繪製專業身體模板需要時間
2. **彈性選擇**：教練可根據需求選擇適合的模板
3. **社群資源**：網路上有大量免費身體圖素材

**建議資源**：
- Freepik（免費身體圖示）
- Flaticon（簡化身體插圖）
- 教練自行拍攝學員照片作為底圖

**實作方案**（Phase 3.1）：
```dart
// 支援從相簿選擇作為底圖
final template = await ImagePicker().pickImage(source: ImageSource.gallery);

// 或使用預設簡易模板
assets/body_templates/
├── simple_body_front.png   // 簡化正面圖（線條）
└── simple_body_side.png    // 簡化側面圖（線條）
```

## 🔧 技術決策

### 可編輯繪圖機制

**問題**：照片標註是否支援重新編輯？

**決定**：✅ **支援重新編輯（向量儲存）**

**實作方式**：

**雙重儲存**：
1. **JSONB 向量路徑**（可編輯）：
   ```json
   {
     "annotations": {
       "circles": [{"center": {"x": 200, "y": 300}, "radius": 30}],
       "arrows": [{"start": {...}, "end": {...}}],
       "texts": [{"position": {...}, "text": "膝蓋內夾"}]
     }
   }
   ```

2. **PNG 圖片**（學員查看）：
   - 渲染向量 → PNG
   - 上傳到 Supabase Storage
   - 學員透過 Signed URL 查看

**編輯流程**：
1. 讀取 JSONB 向量資料
2. 在照片上重繪標註
3. 教練修改標註
4. 儲存新向量 + 重新渲染 PNG

**優點**：
- ✅ 完全可編輯（向量不失真）
- ✅ 學員查看快速（靜態 PNG）
- ✅ 儲存空間小（向量比 PNG 小）

## 📊 效能考量

### Storage 容量優化

**問題**：照片上傳可能快速耗盡 Storage 容量（Supabase 免費 1GB）

**優化策略**：
1. **圖片壓縮**：上傳前壓縮至 720p（Flutter `image` package）
2. **縮圖生成**：自動生成 200x200 縮圖（列表預覽用）
3. **定期清理**：刪除筆記時同步刪除 Storage 檔案
4. **容量監控**：Dashboard 顯示剩餘容量警告

**實作**：
```dart
// 上傳前壓縮
final compressedImage = await FlutterImageCompress.compressWithFile(
  file.path,
  quality: 80,
  minWidth: 720,
  minHeight: 1280,
);

// 生成縮圖
final thumbnail = await FlutterImageCompress.compressWithFile(
  file.path,
  quality: 70,
  minWidth: 200,
  minHeight: 200,
);
```
